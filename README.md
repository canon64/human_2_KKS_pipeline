# human_2_KKS_pipeline

マイクに向かって話しかけると、AIが返事を考えて、その声をゲーム（コイカツ！サンシャイン）の中のキャラクターが喋ってくれる仕組みです。

流れはこうなっています。

```
あなたが話す
   ↓ マイクが自動で録音する
   ↓ 話した内容を文字にする（文字起こし）
   ↓ AIに送って返事を考えてもらう
   ↓ 返事を音声に変換する（読み上げ）
   ↓ ゲームのキャラが喋る・表情が変わる・字幕が出る
```

このソフトは、その全部をつなぐ「配管」です。文字起こし、AI、読み上げは、それぞれ別のソフトが担当します。このソフトはその間を取り持ちます。

## 1. 必要なもの

| 要るもの | 何のために | 無いとどうなる |

## 2. はじめてのインストール

最初の1回だけ、この順でやります。

**手順1.** `setup.bat` をダブルクリックする

必要なプログラムを自動でダウンロードして準備します。数分から十数分かかります。黒い画面が出て文字が流れますが、正常です。終わるまで待ってください。

**手順2.** `launch.bat` をダブルクリックする

設定画面が開きます。これが本体です。

**2回目からは `launch.bat` だけ**でかまいません。`setup.bat` は、動かなくなったときにやり直すためのものです。

### 前のバージョンから乗り換える場合

1. 新しいフォルダに展開する
2. 前のフォルダにある `config.json` を、新しいフォルダにコピーする
3. `launch.bat` を実行する

設定はそのまま引き継がれます。新しく増えた項目には、自動で初期値が入ります。

## 4. ゲーム側プラグインとの連携

このソフト単体では、文字起こしと読み上げまでしかできません。**ゲームの中で何が起きるかは、コイカツ！サンシャイン側に入れるプラグインが決めます。**

プラグインは [canon_plugins](https://github.com/canon64/canon_plugins) にあります。**全部入れる必要はありません。** やりたいことに応じて選んでください。

### 何ができるようになるか

| やりたいこと | 必要なプラグイン | このソフト側の設定 |
|---|---|---|
| キャラに喋らせる・表情を変える | `MainGameVoiceFaceEventBridge` | パイプライン設定タブの送信先 |
| 字幕を画面に出す | `MainGameSubtitleCore` | パイプライン設定タブの字幕送信 |
| 声を出さずキーボードで話しかける | `MainGameSubtitleCore`（入力パネル） | パイプライン設定タブの外部テキスト受信 |
| 会話に合わせてキャラの姿を変える（変身） | `MainGameCharacterMorphBridge` | ゲーム側で合言葉とカードを登録 |
| 変身のときに光らせる | `MainGameGlow` | ゲーム側で設定 |
| 生成した画像を部屋の壁に映す | `MainGameBlankMapAdd` | StableDiffusionタブのBlankMapAdd同期 |
| 動画を部屋で再生する | `MainGameBlankMapAdd` | ゲーム側で設定 |
| Handy（機器）を動きに同期させる **※実験中** | `MainGameHandySync` | ゲーム側で設定 |

**`MainGameHandySync` は実験中です。** 動作が安定しない場合があります。試す場合はその前提で使ってください。

### つながりかた

このソフトは、ゲーム側のプラグインへ**HTTPで送りつける**だけです。ゲームが起動していなくてもこのソフトは動きますし、その逆も同じです。

| 送るもの | 既定のポート | 受け取るプラグイン |
|---|---|---|
| 音声と表情のイベント | `18765` `/voice-face-event` | MainGameVoiceFaceEventBridge |
| 字幕 | `18766` `/subtitle-event` | MainGameSubtitleCore |
| 外部からの手動テキスト（受け取る側） | `18767` `/manual-text` | — |
| スライドショーの状況確認 | `55782` `/slideshow/status` | MainGameBlankMapAdd |

**同じパソコンでゲームを動かすなら、ポートは初期値のままでかまいません。** アドレス（host）だけ `127.0.0.1` にします。別のパソコンで動かす場合は、そのパソコンのIPアドレスを入れます。

### 変身について

「変身」は少し特殊で、**このソフトからは何も設定しません。** 仕組みはこうです。

```
AIが「色黒ギャルになるね」と返事する
   ↓ このソフトが、その文をゲームへ送る（いつも通り）
   ↓ ゲーム側のプラグインが、その文の中の合言葉に気づく
   ↓ 登録されたキャラカードへ、体型や色を時間をかけて変えていく
```

合言葉とキャラカードの組み合わせは、**ゲーム内の設定画面（F1）で登録**します。このソフト側にその設定はありません。

## 6. タブごとの説明

### 6-1. 録音設定タブ

**何をするところ？** マイクの設定をします。「どのマイクを使うか」「どのくらいの大きさの声から録音を始めるか」を決めます。

| 項目 | 意味 | 迷ったら |
|---|---|---|
| 入力デバイス | どのマイクを使うか | 使いたいマイクを選ぶ |
| WAV保存先 | 録音した音の置き場所 | そのままでOK |
| 閾値 | この大きさを超えたら録音開始 | 後述の調整方法を見る |
| 無音停止秒数 | 何秒静かになったら「話し終わった」とみなすか | 0.8秒くらい |
| 最小保存秒数 | これより短い音は捨てる（咳などの誤検出よけ） | 0.5秒くらい |
| 開始前バッファ | 話し始めの何秒前から拾うか | 0.3秒くらい |
| 停止後余韻 | 話し終わりの何秒後まで拾うか | 0.3秒くらい |
| VRプッシュトーク | VRのコントローラのボタンを押している間だけ録音する | VRを使わないならOFF |

**閾値の合わせかた。** 数字が小さいほど敏感になります。

- ひとりでに録音が始まってしまう → 数字を**大きく**する
- 話しても録音が始まらない → 数字を**小さく**する

エアコンや扇風機の音を拾ってしまう場合も、大きくしてください。

### 6-2. パイプライン設定タブ

**何をするところ？** このソフトの心臓部です。「聞き取り → AI → 読み上げ → ゲームへ送る」の各担当と、その接続先を全部ここで決めます。**項目が29個あります。** 上から順に、意味のまとまりごとに説明します。

**最初は上の3分の1だけ埋めれば動きます。** 下の方（LAN送信・字幕送信・外部テキスト受信）は、必要になってから触れば十分です。

#### ① 場所と保存（1〜4行目）

| 項目 | 意味 | 迷ったら |
|---|---|---|
| KKSフォルダ | コイカツ！サンシャインを入れた場所 | ゲームのexeがある場所 |
| 出力先 | 作られた音声やテキストの置き場所 | そのままでOK |
| 保存設定 | 途中経過をファイルに残すか（4つのチェック） | 全部OFFでOK |
| 動作設定 | 応答文字数制限・入力診断ログ | 既定のまま |

**保存設定の4つ。** `Whisperテキスト保存` `元WAV保存` `SBV2入力テキスト保存` `SBV2生成WAV保存`。**普段は全部OFFで問題ありません。** うまく動かないときに、どこで内容が変わったかを追うためのものです。ONにするとファイルが溜まり続けます。

**応答文字数制限。** AIが長々と喋るのを止めます。長い返事は読み上げも長くなるので、テンポを保ちたいならONにします。

#### ② 聞き取り（5〜10行目）

| 項目 | 意味 | 迷ったら |
|---|---|---|
| FasterWhisper Python | 文字起こしプログラムの場所 | 自動で入ります |
| Whisper | 使うモデル（賢さ） | まず `medium`、不満なら `large-v3` |
| FW実行先 | どこで文字起こしするか（下で詳しく） | `ローカルFW` |
| RTFW LAN | サブPCに任せる場合の host / port | 使わないなら空 |
| RTFW操作 | 接続・認証などの手動操作 | 使わないなら触らない |
| RTFW経路 | 送信の段取りの表示 | 表示だけ |

**`FW実行先` は2択です。**

| 選択肢 | 意味 |
|---|---|
| `ローカルFW` | このパソコンで文字起こしする。**1台で使うならこれ** |
| `サブPC RTFW LAN` | 別のパソコン（サブPC）に文字起こしを任せる |

**サブPCに任せると何が良いのか。** 文字起こしはGPUを食います。ゲームと同じパソコンで動かすと、ゲームがカクつきます。**パソコンを2台持っているなら、文字起こしだけサブPCに逃がすと、ゲーム側が軽くなります。**

**サブPCを使う場合の設定。** `FW実行先` を `サブPC RTFW LAN` にすると、下の `RTFW LAN` が効くようになります。ここにサブPCの **IPアドレス** と **ポート** を入れます。サブPC側では、文字起こしサーバー（`run_transcribe_server.py`）を先に起動しておく必要があります。

**1台で完結させるなら、`ローカルFW` のままで、RTFWの3行は無視してかまいません。**

**`RTFW経路`** には `既存WAV → 接続 → 認証 → 音声送信 → ACK → flush → 確定結果` と段取りが表示されます。どこまで進んだかを見るためのもので、設定項目ではありません。

#### ③ 翻訳（11〜12行目）

| 項目 | 中のチェック | 意味 |
|---|---|---|
| あなたの入力 | 翻訳してGrokへ送る | 自分の発言を別の言語に訳してからAIへ渡す |
| | 入力字幕は元の言葉のまま | 画面に出す字幕は訳さず、元の言葉で表示する |
| 女キャラの返事 | 声を翻訳 | 読み上げる音声を別の言語にする |
| | 字幕を翻訳 | 画面に出す字幕を別の言語にする |

**使いどころ。** 日本語で話しかけて英語で返させる、といった使い分けができます。声と字幕を別々に指定できるので、**「英語で喋らせつつ、字幕は日本語」** も可能です。使わないなら全部OFFのままにします。

#### ④ AI（13〜18行目）

| 項目 | 意味 |
|---|---|
| Grok/TTS Python | AI連携と読み上げを動かすPythonの場所 |
| RunPod会話 | クラウド上のAIを使う場合のログイン情報と会話の選択 |
| LLM | どのAIを使うか（バックエンドの選択とモデル名） |
| LLM詳細 | 接続先アドレス・APIキー・temperature・最大トークン・タイムアウト |
| LLM system | AIへの「あなたはこういう役です」という指示 |
| 毎回追加ワード | 毎回こっそり付け足す言葉 |

**`Grok/TTS Python` は重要です。** ここで指定したPythonが、AI連携と読み上げを実行します。**必要なライブラリが入っていないPythonを指定すると、そこで全部止まります。** 迷ったら、このソフトに同梱されているPython（`python\python.exe`）を指定してください。

**LLM詳細の中身。**

| 欄 | 意味 | 目安 |
|---|---|---|
| key | APIキー | ローカルのAIなら適当な文字でOK |
| temp | 返事のばらつき | 0.7前後。上げるほど自由、下げるほど堅い |
| max_tokens | 返事の最大の長さ | 512前後 |
| timeout | 何秒待つか | 120秒前後 |

**LLM system の使いかた。** 「あなたは明るく元気な女の子です。短く返事してください」のように書くと、その口調になります。**左のチェックを外すと、書いた内容を消さずに一時的に無効化できます。**

**毎回追加ワードの使いかた。** ここに書いた言葉は、**字幕にも読み上げにも出ないまま**、AIへの入力にだけ毎回くっつきます。「短く答えて」などの常設の指示に使います。

#### ⑤ 読み上げ（19〜24行目）

| 項目 | 意味 |
|---|---|
| ト書き | `（微笑む）` のような動作説明を読み上げから外す |
| SBV2フォルダ | 読み上げソフト（Style-Bert-VITS2）の場所 |
| SBV2サーバーURL | 読み上げソフトの動かし方と接続先（下で詳しく） |
| SBV2モデル | 使う声のモデル・話者・スタイル・話速 |
| モデルプリセット | 声の設定をまとめて保存・切り替え。自動起動の設定もここ |

#### 声をゲームのキャラ本人にする

**[kks-to-sbv2-pipeline](https://github.com/canon64/kks-to-sbv2-pipeline) を使うと、コイカツ！サンシャインに入っているキャラの音声から、読み上げ用のモデルを作れます。**

普通に読み上げソフトを使うと、返事は「配布されている誰かの声」で喋られます。ゲームの中の女の子が、まったく別人の声で返事をしてくる状態です。これだと違和感が残ります。

このパイプラインでモデルを作ると、**ゲーム本人の声のまま、台本に無いことまで自由に喋ってくれます。** 元のゲーム音声は決まった台詞しか無いのに、そこから学習させることで、AIが考えた新しい返事もその声で聞けるようになります。

作ったモデルは `SBV2フォルダ` に置いて、`SBV2モデル` から選ぶだけです。このソフト側の設定は他に変わりません。

**SBV2サーバーURLとは。** 読み上げソフト（Style-Bert-VITS2）を**どう動かすか**の指定です。3つから選びます。

| mode | 意味 | 使いどころ |
|---|---|---|
| `自動` | サーバーが動いていればそれを使い、無ければローカル実行に切り替える | **迷ったらこれ** |
| `HTTPサーバー` | 常駐しているSBV2サーバーへ、右のURLで繋ぐ | 別のパソコンで動かす／常駐させる |
| `ローカル実行` | 毎回このソフトがSBV2を起動して喋らせる | サーバーを立てたくない |

**URLの入れかた。** 同じパソコンで動かすなら `http://127.0.0.1:5000` が既定です。別のパソコンで動かしているなら、そのパソコンのIPアドレスを入れます。

**`自動起動` のチェック。** 右端にあります。ONにすると、SBV2が動いていないときに自動で立ち上げます。自分で起動しておく手間が省けます。

**どちらが速いか。** `HTTPサーバー` の方が速いです。`ローカル実行` は喋るたびにモデルを読み込み直すので、最初の一言までに時間がかかります。常時使うなら、SBV2を常駐させて `HTTPサーバー` にするか、`自動` ＋ `自動起動` の組み合わせが快適です。

**ト書きはONを勧めます。** OFFだとAIが書いた「（笑顔で）」「*ため息をつく*」といった部分まで声に出してしまいます。画像生成用のプロンプトには影響しません。

**モデルプリセット。** 声の組み合わせを名前を付けて保存できます。キャラごとに声を変えたいときに使います。`自動起動` をONにすると、読み上げソフトを自分で立ち上げなくても済みます。

#### ⑥ ゲームへ送る（25〜29行目）

| 項目 | 意味 | 使うとき |
|---|---|---|
| 送信設定 | 送り先の基本設定と `現在表情維持` | 常に使う |
| 表情送信方式 | 表情の決め方（mode / presetName / ランダム送信） | 常に使う |
| LAN送信 | 音声イベントの送り先（host / port / endpoint / token / HTTP強制） | 常に使う |
| 字幕送信 | 字幕の送り先（host / port / endpoint / token / timeout） | 字幕を出すなら |
| 外部テキスト受信 | 他のソフトから文章を受け取る窓口（host / port / endpoint / token / dedupe） | 外部連携するなら |

**LAN送信が本命です。** ここがゲームとの接続です。同じパソコンでゲームを動かすなら host は `127.0.0.1`、port は `18765` のままでかまいません。別のパソコンなら、そのパソコンのIPアドレスを入れます。

**`HTTP強制`** は、通信方法を強制的にHTTPにする設定です。既定のままで動かないときだけ触ります。

**`現在表情維持`** をONにすると、喋っても表情を変えません。表情の切り替えが不自然に感じるときに使います。

**`ランダム送信`** をONにすると、登録された表情プリセットから毎回ランダムに選びます。

**字幕送信** は、ゲーム画面に字幕を出す機能です。`MainGameSubtitleCore` が要ります。port は `18766` が既定です。

**外部テキスト受信** は、このソフトが**受け取る側**になる窓口です。他のツールから文章を投げ込むと、それをAIに渡して喋らせられます。port は `18767` が既定。`dedupe` は同じ文が連続で来たときに無視する件数です。

### 6-3. Discordタブ

**何をするところ？** Discordを窓口にして、AIとメッセージのやり取りができるようにします。**使わないなら丸ごと無視してかまいません。**

#### 何が嬉しいのか

Discordでメッセージを打つと、**音声と画像と文字が返ってきます。**

```
自分：「おはよう、今日なにしてた？」
   ↓
彼女：ボイスメッセージ（実際に喋った音声）
      画像（そのとき生成された絵）
      テキスト（喋った内容の文字起こし）
```

ゲームを起動していなくても、**スマホのDiscordから**やり取りできます。通勤中でも、寝る前でも、いつもの連絡先の1つとして彼女がいる状態になります。ゲームの中だけの存在だったものが、日常の連絡アプリに出てくる。**まるで本当に彼女とメッセージチャットをしているような感覚**になり、これが想像以上にテンションが上がります。

**こちらからは、文字でも音声でもどちらでも送れます。**

Discordのボイスメッセージや音声ファイルを送ると、**自動で文字起こしされてAIに渡ります。** 手が離せないときは喋って送るだけで済みます。聞き取った内容は「（聞き取り: ○○）」としてチャンネルに表示されるので、正しく伝わったかその場で確認できます。

```
自分：ボイスメッセージを送る
   ↓
（聞き取り: おはよう、今日なにしてた？）   ← 文字起こし結果が返る
   ↓
彼女：ボイスメッセージ＋画像＋テキスト
```

対応している形式は `ogg` `oga` `mp3` `m4a` `wav` `webm` です。スマホのDiscordで録音して送るボイスメッセージはそのまま通ります。

| 項目 | 意味 |
|---|---|
| トークンの環境変数 | Discordのパスワードにあたるものが入っている「環境変数」の名前 |
| .env の場所 | その環境変数を書いたファイルの場所 |
| 送受信先 | **個人DM（推奨）** またはサーバーチャンネル |
| テキストチャンネル | 受信するチャンネルのID／返信先のID |
| 許可サーバー | どのサーバーで動かすか（空なら制限なし） |
| 一覧 | ボットから見えるサーバーとチャンネルのIDを表示する |
| 返信 / 応答待ち | 返事のしかたの調整 |
| 操作 / 状態 | ブリッジの起動・停止と、今の状況表示 |

**大事な注意。** Discordのトークン（パスワードのようなもの）は、この設定画面には直接書きません。別のファイル（`.env`）に書いて、その**名前だけ**をここで指定します。こうすることで、設定を人に渡してもパスワードが漏れません。

#### ボットの作り方

Discordで自分専用のボットを1つ作る必要があります。**無料です。** 上から順にやれば30分ほどで終わります。

> [!CAUTION]
> **先に知っておくこと。**
>
> **この機能は成人向けの会話・画像・音声をDiscordへ送る可能性があります。**
>
> **誤送信、通知への表示、画面共有、サーバーやチャンネルの選択ミスなどによる事故を避けるため、普段使っている本アカウントとは切り離し、新しいメールアドレスで作成した成人向け専用Discordアカウントと専用サーバーを使うことを強く推奨します。**
>
> **登録後に届く確認メールのリンクを踏まないとサーバーは作れません。**
>
> **利用、アカウント管理、公開範囲の設定は利用者自身の責任で行ってください。作者は誤送信や意図しない公開などによって生じた損害について責任を負いません。**

**手順1. ボットを作る**

[discord.com/developers/applications](https://discord.com/developers/applications) を開きます。**ここが出発点です。**

1. **New Application** を押して名前を付ける
2. 左メニューの **Bot** を開く
3. **Reset Token** を押してトークンをコピーする（**一度しか表示されません。** 必ず控えてください）
4. **Privileged Gateway Intents** を設定する
   - **MESSAGE CONTENT INTENT** を **ON**（発言の本文を読むのに必須）
   - **PUBLIC BOT** を **OFF**（他人が勝手に招待できなくなる）
5. 下の **Save Changes** を押す

**手順2. 招待先のサーバーを用意する**

自分だけのサーバーを1つ作ります。Discordの左端の **+** → **オリジナルの作成** → **自分と友達のため**。名前は何でもかまいません。テキストチャンネルは既定の `一般` のままで大丈夫です。

普段使っているサーバーは使わず、この用途だけの専用サーバーを新しく作ることを強く推奨します。

**手順3. ボットをサーバーへ招待する**

手順1のページに戻って続けます。

1. 左メニューの **OAuth2** → **URL Generator**
2. **SCOPES** で `bot` にチェック
3. **BOT PERMISSIONS** で次の4つにチェック
   - View Channels
   - Send Messages
   - Attach Files
   - Read Message History
4. 一番下に出てきたURLをコピーして、ブラウザで開く
5. 手順2のサーバーを選んで **認証** を押す

サーバーのメンバー一覧にボットが増えていれば成功です。

#### 手順3-A. サーバーチャンネル方式を使う場合だけ、他人が入れない状態にする

> [!CAUTION]
> **個人DM方式ではこの作業は不要です。成人向けの会話・音声・画像をサーバーチャンネルで扱う場合だけ、サーバーと使用チャンネルを必ず次の状態にしてください。**
>
> **1. サーバー設定 → ロール → `@everyone` を開き、「権限をクリア」→「変更を保存する」**
>
> **2. 使用チャンネルを「プライベートチャンネル」にして、アクセスできるメンバーを自分とこのボットだけにする**
>
> **3. 招待リンクは作らない。既に作ったものがある場合だけ、サーバー設定 → 招待から削除する**
>
> **このツールの「許可サーバー」だけではチャンネルは非公開になりません。上の3手順も行ってください。**

専用アカウントには、ほかで使っていないパスワードと二要素認証またはパスキーを設定することも推奨します。

**手順4. トークンをファイルに書く**

コピーしたトークンを `.env` というファイルに書きます。**設定画面には貼りません。**

```
DISCORD_PRIVATE_BOT_TOKEN=（手順1でコピーしたトークン）
```

`.env` はツール本体のフォルダへ置きます。Discordタブの **「.env の場所」** には最初からこの場所が入ります。変数名（`DISCORD_PRIVATE_BOT_TOKEN` の部分）は **「トークンの環境変数」** に入れます。名前は自分で決めてかまいませんが、両方を一致させてください。

**手順5. 個人DMを設定する（推奨）**

Discordタブで **「送受信先」を「個人DM（推奨）」** にします。ユーザーIDの入力は不要です。BotへDMを送ると、返事・画像・音声が同じDMへ返ります。

ボットをサーバーへ入れるのは、Discord上で自分とボットを接続するためだけです。成人向けの内容をサーバーのチャンネルへ投稿する必要はありません。

サーバーチャンネル方式を使いたい場合だけ、次の設定を使います。

Discordタブの **「チャンネル一覧を取得」** ボタンを押すと、ボットから見えるサーバーとチャンネルのIDが一覧に出ます。そこから使いたいものを選んで、上の欄に貼り付けます。

| 欄 | 入れるもの |
|---|---|
| 許可サーバー | 手順2のサーバーのID |
| テキストチャンネル（受信） | 使うチャンネルのID |
| テキストチャンネル（返信先） | 空でよい（受信と同じ場所に返します） |

**手順6. 動かす**

**「設定を保存」** を押してから、**「ブリッジ起動」** を押します。状態欄が動いていれば接続できています。

スマホのDiscordでボットとの個人DMを開き、メッセージを送ってみてください。返事が返ってくれば完成です。

#### うまくいかないとき

| 症状 | 原因 |
|---|---|
| ボットがオフラインのまま | トークンが違う。`.env` の変数名と設定欄の名前が一致しているか確認 |
| 発言に反応しない | **MESSAGE CONTENT INTENT** がOFF。手順3-4をやり直す |
| 一覧にサーバーが出ない | ボットを招待していない。手順4をやり直す |
| 返事が書き込まれない | チャンネルIDが違う、またはSend Messages権限が無い |

### 6-4. StableDiffusionタブ

**何をするところ？** AIの返事に合わせて、AI画像を自動生成します。**使わないなら無視してかまいません。**

| 項目 | 意味 |
|---|---|
| A1111 API | 画像生成ソフト（AUTOMATIC1111）の接続先 |
| 永続生成 | 止めるまでずっと作り続けるかどうか |
| プロンプトタグ | AIの返事から絵の指示を切り出すための目印 |
| BlankMapAdd | ゲーム内のスライドショーと歩調を合わせる（下で詳しく） |
| モデル / 追加プロンプト / Negative | 絵柄の指定 |
| 生成 / Seed/Batch / 保存 | 枚数やサイズの設定 |
| Hires.fix ほか | 高解像度化の設定 |
| テストprompt / テスト | 試し撃ち用 |

画像生成ソフトを別に用意して、起動しておく必要があります。

#### BlankMapAdd同期とは

ゲーム側のプラグイン（MainGameBlankMapAdd）には、部屋の壁に画像を順番に映すスライドショーがあります。**このソフトが作った絵を、そこへ流し込むための連携**です。

**何が困るのか。** 永続生成をONにすると、絵がどんどん作られます。何も考えずに作り続けると、ゲーム側がまだ1枚目を映している最中に2枚目3枚目ができてしまい、見る前に流れていきます。

**この同期がすること。** 次の絵を作る前に、ゲーム側へ「いま何を映してる？」と聞きに行きます。まだ前の絵を映している最中なら、作るのを待ちます。映し終わっていたら次を作って、「新しいのができたよ」と知らせます。**結果として、見るペースに合わせて生成されます。**

| 項目 | 意味 | 既定値 |
|---|---|---|
| BlankMapAdd同期 | この連携を使うか | ON |
| host | ゲームが動いているパソコンの場所 | `127.0.0.1`（同じパソコン） |
| port | 問い合わせ先の番号 | `55782` |
| endpoint | 問い合わせるページ名 | `/slideshow/status` |
| timeout | 何秒待って諦めるか | `1.0` |

**使わない場合はOFFにしてください。** ONのままゲーム側が起動していないと、問い合わせが毎回失敗してログに警告が出続けます（動作自体は止まりません）。ログにはこう出ます。

```
[sd-forever][blankmap] status failed ... hint=BlankMapAdd同期先が未起動/ポート違い。使わないならBlankMapAdd同期をOFF
```

**同じパソコンでゲームを動かしているなら、host と port は初期値のままでかまいません。**

### 6-5. テストタブ

**何をするところ？** 各部品が正しく動くか、1つずつ確かめます。**うまくいかないときは、まずここです。**

| ボタン | 何が試せるか |
|---|---|
| 押して話す（離して判定） | マイクと文字起こしが動くか |
| 入力テキストでテスト | 文字を打ってAIの返事を試す（マイク不要） |
| 送信前テスト | ゲームへ送る直前の状態を確認 |
| SBV2テスト実行 | 読み上げが鳴るか |
| 最後の音声をGUI再生 | 直前に作られた音をこの画面で鳴らす |
| 現在表情維持 | 表情を変えずに喋らせる |

**切り分けのコツ。** 「押して話す」で文字が出れば、マイクと文字起こしは正常です。そこから先で止まっているなら、AIか読み上げの設定を見ます。

### 6-6. 変換辞書タブ

**何をするところ？** 読み上げソフトが変な読み方をする言葉を、正しい読みに直します。

表は6列あります。

| 列 | 意味 |
|---|---|
| 有効 | この行を使うか |
| 変換前 | 元の言葉 |
| SBV2送信用 | 読み上げに渡すときの書き換え後 |
| 表示用 | 字幕に出すときの書き換え後 |
| 表示適用 | 字幕にも適用するか |
| 登録順 | 並び順 |

**なぜ2列に分かれているのか。** 読み上げと字幕で、欲しい形が違うからです。例えば「KKS」を、字幕では `KKS` のまま出したいけれど、読み上げには `ケーケーエス` と渡したい、という使い分けができます。

**プリセット** は、辞書のセットをまるごと保存して切り替える機能です。

### 6-7. 文字起こし変換タブ

**何をするところ？** 使いかたは変換辞書と同じですが、**タイミングが違います。**

- **文字起こし変換** … 聞き取った直後。AIに送る**前**
- **変換辞書** … AIの返事ができた後。読み上げに送る**前**

聞き取りの間違いを直したいときはこちら（例：「ルナ」を「るな」と誤認する → 直す）。読み方を直したいときは変換辞書です。

### 6-8. Seleniumタブ

| ボタン | 何をするか |
|---|---|
| Chrome起動 | 専用のChromeを立ち上げる |
| Selenium接続 | そのChromeにつなぐ |
| Grokを開く（テスト） | 実際にページを開いて確かめる |
| Chrome終了 | 閉じる |
| ヘッドレス | 画面を出さずに動かす |

**手順は「Chrome起動 → Selenium接続」の順です。** 逆にすると繋がりません。

### 6-9. ワード連動追記タブ

**何をするところ？** 特定の言葉を喋ったときだけ、AIへこっそり資料を渡します。

表は4列です。

| 列 | 意味 |
|---|---|
| 有効 | この行を使うか |
| ワード | 反応する言葉 |
| 種別 | 直接書くか、ファイルから読むか |
| 送る文言 / ファイルのパス | 渡す内容 |

**使いかたの例。** ワードに `曲` 、送る内容に曲名リストのファイルを指定しておきます。すると「何か曲かけて」と言ったときだけ、AIに曲の一覧が渡ります。AIはその中から選んで答えられます。

**渡した内容は読み上げられません。** 字幕にも出ません。AIに見せるだけです。

一番上の **「ワード連動追記を使う」** のチェックを外すと、登録を消さずに全部止められます。

### 6-10. フィルタータブ

**何をするところ？** **文字起こし（FasterWhisper）が拾ってしまった、いらない発言を捨てます。** ここに登録した言葉が聞き取り結果に含まれていると、**その発言まるごと無かったことにして、AIには送りません。**

掛かる場所はここです。

```
あなたが話す → 文字起こし（FasterWhisper） → ★ここでフィルター★ → AIへ送る
```

| 列 | 意味 |
|---|---|
| 有効 | この行を使うか |
| パターン | 引っかける言葉 |
| 種別 | 一致のしかた（部分一致 / 完全一致 / 正規表現） |
| 登録順 | 並び順 |

**なぜ必要か。** 文字起こしは、無音や物音を勝手に言葉として拾うことがあります。特に有名なのが、何も喋っていないのに「ご視聴ありがとうございました」「チャンネル登録お願いします」が出てくる現象です。放っておくと、その幻の発言にAIが返事をしてしまいます。

**使いかたの例。**

| パターン | 種別 | 効果 |
|---|---|---|
| `ご視聴ありがとうございました` | 部分一致 | この文が混ざった発言を捨てる |
| `チャンネル登録` | 部分一致 | 同上 |
| `おわり` | 完全一致 | 「おわり」だけの発言を捨てる（長い文の中の「おわり」は残る） |

**種別の使い分け。** 迷ったら部分一致で十分です。完全一致は「その言葉だけを言ったとき」に限定したい場合、正規表現は複雑な条件を書きたい場合に使います。

**捨てられたときはログに出ます。** 動いていないように見えたら、ログを見てください。

```
[filter] 除外: ご視聴ありがとうございました
```

**AIの返事を整える機能ではありません。** 返事の言い回しを直したいときは変換辞書タブ、AIの口調を変えたいときはパイプライン設定タブの「LLM system」を使ってください。

### 6-11. ベクター返答タブ

**何をするところ？** 過去の会話を貯めておいて、**似た話題のときに昔の返事を再利用**します。AIに毎回考えさせるより速く、口調も安定します。

| 項目 | 意味 |
|---|---|
| Grok履歴ベクター返答を使う | この機能のON/OFF |
| 検索API | 過去ログを探す係の場所 |
| 候補選択 | 一番近いものを使うか、近いものからランダムに選ぶか |
| 検索タイムアウト | 何秒待つか |
| フォールバック | 見つからなかったとき、AIに聞き直すか |
| 読み上げの改行目安 | 何文字くらいで区切るか |
| 必須語ルール / 返答の必須語 / 優先語 | 返事に必ず入れたい言葉、なるべく入れたい言葉 |
| 期間 | いつからいつまでの会話を対象にするか |
| 起動時に検索APIを自動で立ち上げる | 自動で準備する |
| 必要ならOllamaも自動で起動する | 検索に使うソフトも自動で立ち上げる |
| Grok履歴を更新 | 新しい会話を取り込む |

**過去ログが無いと何も起きません。** 先に会話履歴を手に入れて、取り込む必要があります。

#### 手順1. Grokから会話履歴を書き出す

Grokのサイトで、自分の会話履歴を丸ごと書き出します。

```
設定
 → データコントロール
 → アカウントデータをエクスポート
 → アカウントデータをダウンロード
 → （登録アドレスにメールが届くのを待つ）
 → メール内のリンクからデータをダウンロード
```

申請してすぐには届きません。メールが来るまで時間がかかるので、待ってください。届いたらzipファイルがダウンロードできます。

#### 手順2. 取り込む

ダウンロードできるのは、`2183a4ae-f134-4076-9821-ffbed25e59a4.zip` のような**でたらめな名前のzipファイル**です。名前は毎回変わります。

**このzipは展開しません。そのまま置きます。**

```
human_2_KKS_pipeline/
  grok_history/
    incoming/          ← ここにzipをそのまま入れる
      2183a4ae-....zip
```

置いたら、**「Grok履歴を更新」**ボタンを押します（`update_grok_history.bat` をダブルクリックしても同じです）。

**よくある間違い。** zipを展開して中のファイルを置いても取り込まれません。取り込む側がzipを開いて、中の `prod-grok-backend.json`（会話の本体。100MB近くあります）を自分で探す作りになっているためです。展開したフォルダを置いても無視されます。

**中身について。** zipには画像などの添付も大量に入っていますが、気にしなくて大丈夫です。必要なものだけ自動で拾います。

**同じzipを何度置いても平気です。** 取り込み済みの会話は自動で飛ばされるので、重複しません。過去のzipを全部入れておいても問題ありません。

**取り込みが終わったzipは自動で移動されます。** `runtime/data/grok_export_index/sources/` へ退避されるので、`incoming` から消えていたら成功しています。

**Ollama の準備は自動で案内されます。** 取り込みの最後で Ollama というソフトを使いますが、足りないものがあれば「Grok履歴を更新」を押した時点でポップアップが出ます。次を読んでおけば迷いません。

#### 手順3. Ollama を用意する（案内が出たときだけ）

**Ollama とは。** 文章を「数字の並び」に変換するソフトです。この数字にすると、意味の近さを計算で比べられます。「昨日なに食べた？」と「昨日の晩ごはんは？」が似ている、と機械に判断させるために使います。この変換をこのソフト自身は持っていないので、Ollamaに任せています。

**「Grok履歴を更新」を押すと、足りないものを自動で調べます。** 出るポップアップは2種類です。

**その1：Ollama が入っていない場合**

機能の説明と一緒に「ダウンロードページを開きますか？」と聞かれます。**はい**を押すと [ollama.com](https://ollama.com) が開くので、Windows版を入れてください。入れ終わったら、もう一度「Grok履歴を更新」を押します。

**その2：モデルが入っていない場合**

「今すぐインストールしますか？」と聞かれます。**はい**を押すと、その場でモデル（`bge-m3`）の取得が始まります。

- 数GBあるので、回線によっては数分から十数分かかります
- 取得中は画面が固まりますが、進み具合はログ欄に出ます
- **1回入れれば、次回からは聞かれません**

**両方そろっていれば、ポップアップは出ません。** そのまま取り込みが始まります。

**自分で用意したい場合。** コマンドプロンプトで次を実行しても同じです。

```
ollama pull bge-m3     入れる
ollama list            確認（一覧に bge-m3 が出ればOK）
```

**起動について。** 毎回自分で起動する必要はありません。ベクター返答タブの **「必要ならOllamaも自動で起動する」をON** にしておけば、必要なときにこのソフトが勝手に立ち上げます。

- 既にOllamaが動いていれば、それをそのまま使います（勝手に落としたりしません）
- 自分で起動していない場合だけ、このソフトが起動します。その場合はGUIを閉じると一緒に終了します
- `ollama.exe` の場所は自動で探します（標準のインストール先なら設定不要）。見つからない場合だけ、`Ollama実行ファイル` の欄に手で指定してください

| 設定項目 | 既定値 | 意味 |
|---|---|---|
| Ollama接続先 | `http://127.0.0.1:11434` | Ollamaの待ち受け先。同じパソコンならそのまま |
| Ollama実行ファイル | 空欄 | 空なら自動で探す |
| 埋め込みモデル | `bge-m3:latest` | **今は変更できません**（後述） |

**別のパソコンでOllamaを動かしている場合**は、接続先にそのIPアドレスを入れます。ただしその場合、こちらから起動はできないので、向こう側で先に立ち上げておいてください。

**「埋め込みモデル」欄について。** 画面には入力欄がありますが、**現状この値は使われません。** 埋め込み処理はコード側で `bge-m3:latest` に固定されています。別のモデル名を入れても `bge-m3` が使われるので、**触らないでください。**

#### 手順4. 検索の準備

過去ログを探す係のプログラム（検索API）が動いている必要があります。

**「起動時に検索APIを自動で立ち上げる」をON** にしておけば、GUIを起動したときに自動で用意されます。手動で動かす場合は、検索APIのポート（既定 `8877`）に合わせて自分で起動してください。

## 7. はじめて使う人の設定順

いきなり全部やろうとすると必ず迷います。**この順番で、1つずつ動作を確かめながら**進めてください。

**第1段階：声が文字になるか**

1. 録音設定タブで、マイクを選ぶ
2. テストタブの「押して話す」で喋る
3. 文字が出れば成功

出ないときは、マイクの選択と閾値を見直します。

**第2段階：AIが返事をするか**

1. パイプライン設定タブで、AIの接続先を入れる
2. テストタブの「入力テキストでテスト」に文字を打つ
3. 返事が返れば成功

**第3段階：声が出るか**

1. パイプライン設定タブで、SBV2の場所を入れる
2. テストタブの「SBV2テスト実行」を押す
3. 音が鳴れば成功

**第4段階：ゲームに届くか**

1. ゲームを起動して、受信プラグインを入れておく
2. パイプライン設定タブで送信先を入れる
3. テストタブの「送信前テスト」で確認

**第5段階：好みに調整する**

ここまで動いたら、辞書・フィルター・ワード連動追記などを足していきます。

設定は `config.json` に保存されます。

**このファイルは他人に渡さないでください。** パスワードやアクセスキーが入っています。

## 9. 困ったとき

### 起動しない、`No module named ...` と出る

準備が終わっていません。`setup.bat` をもう一度実行してください。

### Selenium（Chrome）につながらない

「Chrome起動 → Selenium接続」の順で押しているか確認してください。既にChromeを普通に開いている場合は、いったん全部閉じてからやり直します。

### `model_assets not found` と出る

読み上げ用の音声モデルが見つかっていません。SBV2フォルダの指定が正しいか確認してください。

### 音が鳴らない、`WinError 10061` と出る

読み上げソフト（SBV2）が起動していません。先にそちらを立ち上げてください。

### 動くけれど返事が変

- 前置きが多い → フィルタータブで消す
- 読み方が変 → 変換辞書タブで直す
- 聞き取りが違う → 文字起こし変換タブで直す
- 口調を変えたい → パイプライン設定タブの「LLM system」を書き換える

### どこで止まっているかわからない

テストタブで1つずつ試してください。第1段階から順に確かめると、どこで切れているかがわかります。

## 10. 開発者向け

### 起動方法

```
launch.bat                    配布向け（同梱Pythonを使う）
python main.py                venv等で動かす場合
```

### 個別のエントリポイント

| ファイル | 用途 |
|---|---|
| `run_transcribe_server.py` | 文字起こしサーバー |
| `run_transcribe_one_wav.py` | WAV1本を文字起こし |
| `run_grok_tts_event.py` | AI応答から読み上げ・イベント送信まで |
| `run_sd_prompt_receiver.py` | 画像生成プロンプトの受け取り |
| `run_grok_history_update.py` | 会話履歴の取り込み |
| `run_telegram_bridge.py` | Telegram連携 |
| `discord_bridge/run_bridge.py` | Discord連携 |

### 主なフォルダ

| 場所 | 中身 |
|---|---|
| `gui/` | 画面 |
| `controllers/` | 設定の読み書き |
| `workers/` | パイプラインの実行 |
| `grok_bridge/` | AI連携と読み上げ・送信 |
| `grok_history/` | 会話履歴の取り込みと検索 |
| `discord_bridge/`, `telegram_bridge/` | 外部チャット連携 |
| `core/`, `services/` | 共通処理 |
| `config/` | 設定の型とプリセット |

### 追跡しないもの

`config.json`（個人設定）、`appends/`（曲や衣装の一覧などの環境依存データ）、`_logs/`、`outputs/`、会話履歴の実データは、リポジトリに含めません。
